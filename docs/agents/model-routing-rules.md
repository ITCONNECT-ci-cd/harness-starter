# 작업별 모델 배정

일반 작업은 `.codex/config.toml`의 Astra / High 기본값으로 직접 처리한다. 아래 기준은 역할과 모델을 선택하는 운영 지침이며, 파일만으로 난이도를 판정하는 자동 실행기는 아니다. 역할별 실행 값은 `.codex/agents/`의 해당 TOML을 읽는다.

## 역할 선택

| 상황 | 역할 파일 | 책임 |
|---|---|---|
| 여러 모듈의 의존성·설계 선택이 복잡한 Epic | `harness-planner.toml` | 계획·위험·분할안을 읽기 전용으로 검토 |
| 요구사항·수정 파일·수락 기준이 명확한 독립 구현 | `harness-worker.toml` | 맡은 범위 구현과 관련 테스트. 프로젝트가 구현 위임을 허용할 때만 사용 |
| 코드 탐색·로그 분석·자료 정리 | `harness-explorer.toml` | 읽기 전용으로 근거와 요약 반환 |
| 일반적인 독립 코드 리뷰 | `harness-reviewer.toml` | 정확성·회귀·테스트 근거 검토 |
| 원인 불명 장애·동시성·권한/데이터 경계의 어려운 검토 | `harness-deep-reviewer.toml` | 읽기 전용 심층 분석. 일반 리뷰어에 추가하는 대신 필요 시 대체 |

기존 프로젝트의 DIRECT_CODEX_ONLY, 단일 리뷰어, 중첩 금지, Orca, Phase A/B 역할·검증·실패 중단 규칙을 유지한다. 이 문서와 프로필은 위임 권한을 추가하지 않는다. 해당 프로젝트에 없는 역할 파일을 만들거나 다른 모델로 우회하지 않는다.

## 실행 기준

- 작은 수정은 주 에이전트가 직접 처리한다. 위임은 승인된 범위에서 독립 작업을 분리할 이점이 있을 때 사용한다. 작업의 길이보다 모호함·의존성·실패 영향을 함께 평가한다.
- 하위 에이전트를 생성할 때 선택한 역할의 `model`과 `model_reasoning_effort`를 함께 지정한다. 프로필 로딩을 지원하면 TOML의 `name` 필드로 커스텀 역할을 호출하며 파일명에서 호출 이름을 추정하지 않는다. 생성 도구에 모델 인자만 있으면 해당 두 값과 역할 지침을 명시적으로 전달한다. 설정을 생략한 채 상속 결과를 다른 모델 사용으로 보고하지 않는다.
- 모델 변경을 허용하지 않는 전체 대화 복제 방식은 사용하지 않는다. 필요한 목표·파일 범위·제약·근거만 전달하는 새 문맥을 사용한다. 모델이나 도구가 지원되지 않으면 이를 보고하고, 권한 안의 순차 작업 또는 명시적으로 선택한 대안을 사용한다. 필수 독립 승인은 미완료로 유지한다.
- 복잡한 Epic 전체를 Extra High 주 에이전트가 총괄하려면 작업 시작 시 주 에이전트의 모델·추론을 명시적으로 선택한다. High로 실행 중인 주 에이전트가 스스로 설정을 바꿨다고 가정하지 않는다. 진행 중에는 planner 또는 deep reviewer에게 범위가 정해진 판단을 맡길 수 있다.
- 주 에이전트는 목표·수락 기준·파일 소유권·허용 검증을 전달하고 최종 통합·검증에 책임진다. 하위 에이전트는 추가 에이전트 생성, 의존성 설치, commit·push·배포를 하지 않는다. 공유 파일의 동시 편집을 피한다.
- 실패 원인이 권한·자격증명·환경 누락이면 모델을 올려 재시도하지 않는다. 추론 부족이 의심될 때만 구체적인 미해결 근거를 전달해 재분석하며, 모델 교체로 기존 실패 횟수나 승인 상태를 초기화하지 않는다.
- 코드·문서 편집은 승인 범위 안에서만 한다. 읽기 전용 역할의 결과를 반영할 편집은 주 에이전트가 수행한다. 모델을 낮춰도 테스트·데이터 보호·독립 승인 기준은 낮추지 않는다.

## 적용과 관찰

커스텀 에이전트는 Codex용이며 Claude Code의 모델 설정을 바꾸지 않는다. 앱의 현재 작업 설정과 시스템 권한이 우선할 수 있으므로 생성 시 요청한 모델·추론과 반환된 실행 정보를 구분해 기록한다. 파일 검사를 실제 앱 로딩이나 모델 품질 검증으로 보고하지 않는다.

대표 구현·리뷰·조사 작업에서 성공 여부, 재수정 횟수, 완료 시간과 확인 가능한 사용량을 비교한다. 비교 결과가 쌓이기 전에는 High 또는 혼합 모델의 품질·속도·비용 개선을 보장하지 않는다. 초기에는 적은 수의 독립 작업부터 적용한다.
