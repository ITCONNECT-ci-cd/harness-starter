# 프로젝트 이해 문서 계약

## project-map 준비

이 Starter는 project-map 스킬을 번들하지 않는다. 일반 Git·설정·Harness 유지보수의 필수 의존성은 아니지만, Phase C 문서 생성·갱신 전에 아래 준비가 필요하다.

1. 프로젝트 초기화에서 저장소의 `.agents/skills/project-map/SKILL.md`·`.claude/skills/project-map/SKILL.md`, 도구가 제공한 스킬 목록, 전역 스킬 경로에서 실제 설치를 확인한다. 후보가 여러 개면 명시적 사용자 지정 경로와 프로젝트 설치를 우선한다.
2. 발견한 스킬의 실제 `SKILL.md`를 읽고 경로·출처·버전(또는 커밋/파일 해시)·산출물·재생성 명령을 프로젝트 `docs/decisions/`의 준비 기록에 남긴다. 이름만으로 설치됐다고 판단하지 않는다.
3. 찾지 못하면 확인한 경로와 누락을 보고하고 조직에서 사용하는 원본 스킬 경로 또는 저장소 URL을 요청한다. 승인된 원본을 도구의 스킬 설치 방식으로 설치하거나, 저장소 설치라면 양쪽 스킬 트리에 동일하게 배치하고 동기화를 검증한다. 출처를 추측하거나 같은 이름의 대체 스킬을 임의 생성하지 않는다.
4. 설치가 해결되지 않아도 독립적인 회고·수정·검증은 계속한다. 필요한 이해 문서 단계는 미완료로 남기고 Phase C 전체가 끝났다고 보고하지 않는다.

기존 프로젝트에 Harness만 설치하는 `scripts/install.*`는 BMAD와 project-map 스킬을 설치하거나 덮어쓰지 않는다. 공통 실행 규칙은 `docs/agents/`를 통해 적용한다.

## 산출물과 선택 문서

- `docs/PROJECT_MAP.md`: 코드 근거로 생성·갱신하는 필수 지도. §0 갱신 트리거, §9 구조적 함정, 마지막 Epic의 §10 규칙 색인을 관리한다. 실제 스킬의 장 구조가 이 계약과 다르면 매핑을 준비 기록에 명시하고 누락을 해결한다.
- `docs/SPEC.html`: 사람용 제품 명세. 이미 있으면 관련 화면·라우트·규칙이 바뀔 때 갱신한다. 신규 생성은 사용자의 요청 또는 한 번의 생성 동의가 필요하다.
- 추가 사람용 문서: 고정된 “2종”을 임의로 만들지 않는다. 파일명·대상 독자·범위를 사용자 요청 또는 승인된 산출물 목록에서 확인한다.
- 마지막 Epic의 §10 생성·검증은 선택적인 사람용 HTML 생성 여부와 별개다. 사람용 문서를 거절해도 §10을 생략하지 않는다. 선택 질문의 답을 기다리는 동안 지도·색인·검증은 진행한다.
- `docs/*.html`은 일상적인 코드 맥락 수집에 로드하지 않는다. 요청된 문서 검토·생성·갱신·검증에는 필요한 범위의 읽기를 허용한다.

## 검증과 완료 보고

- 마지막 Epic 판정은 `workflow-rules.md`의 정확한 키·상태·기획 목록 기준을 사용한다. 회고 키, 빈 목록, 누락 파일을 근거로 마지막이라고 추정하지 않는다.
- 스킬에 포함되거나 해당 프로젝트를 위해 작성한 재생성·검증 스크립트를 리포에 보관한다. 명령, 입력 범위, 산출물, 기준 커밋을 준비 기록에 적는다.
- 코드→문서 누락과 문서→코드 불일치, 참조 경로 부재, 근거가 사라진 항목을 실제 스크립트로 검증한다. 0건인지 확인하고, 남은 항목이 있으면 필수 문서 단계는 미완료다. 실행하지 않은 검증을 통과로 보고하지 않는다.
- 완료 보고에 변경한 장, 사용한 스킬 경로·버전, 재생성·검증 결과, 사람용 문서의 생성/갱신/거절/응답 대기 상태를 구분한다.
