# 26.10.03 PowerShell 스크립트의 Windows PowerShell 5.1 호환

> [전체 변경 이력](README.md) · 선행: [구현 워커를 bmad-build-auto로 교체](2026-10-03-bmad-build-auto.md)

## 회의에서 설명할 핵심

**이 하네스의 `.ps1` 스크립트 일부가 Windows PowerShell 5.1(`powershell.exe`)에서 돌지 않았습니다.** PowerShell 7(`pwsh`)에서는 모두 정상이라 기존 CI(PowerShell 7 파싱 검사)로는 드러나지 않았습니다. Windows의 Codex 워커는 `powershell.exe`를 쓸 수 있고, 설명서는 "Windows PowerShell"에서 `preflight.ps1`·`finalize-story.ps1`을 실행하라고 안내합니다.

**원인은 두 가지입니다.**

1. **BOM 없는 UTF-8 한글.** 5.1은 BOM이 없으면 파일을 시스템 코드 페이지로 읽습니다(한국어 Windows는 CP949). 한글이 깨지고 깨진 글자가 문자열의 닫는 따옴표를 삼켜 파싱 오류가 납니다. 오류 메시지에 `?덉긽怨??ㅻ쫫"` 같은 글자가 찍혔습니다.
2. **없는 것을 조용히 확인하는 git 호출.** 스크립트는 `$ErrorActionPreference = "Stop"`입니다. 5.1은 네이티브 명령이 stderr에 쓰면 `*> $null`·`2> $null`로 버려도 예외를 던지고, PowerShell 7은 던지지 않습니다. 그래서 `git rev-parse --verify <없는 ref>`나 `git remote get-url origin`(origin 없음)이 5.1에서만 스크립트를 죽였습니다. 새 프로젝트에서 `origin/develop`이 아직 없을 때가 대표적입니다.

## 변경 전후

| 자리 | 변경 전 (5.1) | 변경 후 (5.1) |
|---|---|---|
| `install.ps1`, `setup/init-harness.ps1`, `setup/setup-repo.ps1` | 파싱 오류 5건·4건·1건, 실행 불가 | 파싱 오류 0건 |
| 비ASCII가 있으나 파싱은 통과하던 6개 파일 | 한글이 깨질 수 있음 | BOM 추가 |
| `validate-quick.ps1` (`origin/develop` 없음) | `fatal: Needed a single revision`으로 실패, 종료 코드 1 | PASSED |
| `finalize-story.ps1` 새 Story 브랜치 만들기 경로 | 브랜치 존재 확인에서 예외 | 브랜치를 만들고 종료 코드 0 |
| `preflight.ps1` (`develop`·`origin` 없음) | 안내 메시지 대신 날것의 예외 | "초기화를 먼저 완료하세요" 안내 |
| `setup/init-harness.ps1` (origin 없음) | 예외 | `SKIP - git origin 미설정` 안내 |
| `doctor.ps1` (origin 없음) | 예외 | `[WARN] origin remote not configured` |

표의 "변경 전" 열 중 `validate-quick.ps1`만 수정 전 스크립트를 5.1에서 직접 실행해 실패를 확인했습니다. 나머지 행은 같은 형태의 git 호출이 5.1에서 예외를 던진다는 시험(아래 검증)으로 확인했고, 해당 스크립트를 수정 전 상태로 각각 실행해 보지는 않았습니다.

## 검증

실행해서 확인한 것:

- 모든 `scripts/**/*.ps1` 16개의 파싱 오류: Windows PowerShell 5.1과 PowerShell 7 모두 0건 (수정 전 5.1에서 3개 파일 10건).
- 5.1 기준선 비교: BOM을 붙이기 전후로 `validate-quick`, `validate`, `smoke`의 출력이 같고, `doctor`는 점검 18개가 같음(브랜치에 따라 달라지는 `gh api current ref` 1줄 제외).
- `install.ps1 -DryRun`을 5.1에서 실행: 한글 출력 정상, 종료 코드 0, 대상 폴더에 아무것도 쓰지 않음.
- git 호출 형태 시험(5.1/7): `*> $null`·`2> $null`·`> $null 2>&1`은 5.1에서 예외, `--quiet`와 `git config --get`은 5.1·7 모두 예외 없음. 없는 ref에서 1, 있는 ref에서 0.
- 수정 전 `validate-quick.ps1`(main)을 5.1에서 직접 실행해 같은 `fatal: Needed a single revision` 실패를 확인.
- origin·develop이 없는 임시 저장소에서 5.1과 7 모두: `validate-quick` PASSED, `preflight` 안내 메시지(종료 코드 1은 의도), `finalize-story`(새 브랜치) 종료 코드 0, `init-harness` SKIP, `doctor` WARN.
- 시험의 음성 검증: BOM을 떼면 BOM 시험이 실패하고, `validate-quick.ps1:28`의 `--quiet`를 되돌리면 그 줄을 짚어 실패, 복원하면 통과. 이 시험은 `doctor.ps1:62`에서 제가 놓친 호출도 실제로 잡았습니다.
- 스타터 자체 검증(`harness-self-test.yml` 단계): `bash -n` 12개 실패 0건, node 테스트 `orca-scripts` 19개와 `ps51-compat` 4개 통과, 스킬 트리 동기화, `validate(-quick)` `.sh`/`.ps1` PASSED (template 모드). 보안 단계의 경고 1건은 `scripts/validate.ps1:179`의 검색 패턴이 자기 자신과 일치한 기존 오탐입니다.

## 남은 항목

| 항목 | 내용 |
|---|---|
| 같은 종류의 다른 호출 | git 저장소 밖에서 실행할 때만 stderr를 쓰는 호출은 고치지 않았습니다: `git rev-parse --is-inside-work-tree *> $null`(`lib/package-runner.ps1:80`, `lib/validate-utils.ps1:347`)과 `git rev-parse --show-toplevel 2>$null`. 하네스는 git 저장소 안에서 돌고 이 경우 5.1에서 폴백 대신 예외가 납니다. |
| `2>&1`로 합치는 git 호출 | `lib/git-utils.ps1`의 `Invoke-HarnessGit` 등은 다른 방식으로 오류를 처리하므로 건드리지 않았습니다. 5.1에서 `git fetch`·`push`가 진행 표시를 stderr에 쓸 때의 동작은 확인하지 못했습니다. |
| 실제 Codex 워커 | Codex가 실제로 `powershell.exe` 5.1을 쓰는지는 확인하지 못했습니다. 이 수정은 5.1에서 돌 수 있게 하는 것이며, 워커 환경을 확인한 결과가 아닙니다. |
| 한국어가 아닌 Windows | 코드 페이지 949에서만 시험했습니다. BOM을 붙였으므로 다른 코드 페이지에서도 UTF-8로 읽혀야 하지만 직접 확인하지는 못했습니다. |
