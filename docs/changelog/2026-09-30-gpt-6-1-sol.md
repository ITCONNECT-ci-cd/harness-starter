# 26.09.30 GPT-6.1 Sol 교체

> [전체 변경 이력](README.md) · [같은 날 선행 기록: Orca 모델 배정 승인 방식](2026-09-30-orca-model-approval.md) · [모델 배정 규칙](../agents/model-routing-rules.md)

OpenAI가 2026-09-29 DevDay에서 GPT-6.1 Sol을 발표해, 하네스의 네 모델 중 GPT-6 Sol을 GPT-6.1 Sol로 바꿨습니다. 역할과 선택 표는 그대로 두고, 모델 이름·Codex 설정·effort 주의사항만 고쳤습니다.

## 회의에서 설명할 핵심

**Sol이 맡는 일은 바뀌지 않습니다.** GPT-6.1 Sol은 여전히 연계 작업(여러 파일 구현, 리팩터링, 통합), 위험 높은 정형 작업, Sonnet·Opus가 쓴 코드의 리뷰를 맡습니다. OpenAI도 이 모델을 복잡한 리팩터링, 깊은 코드베이스 조사, 오래 도는 에이전트용으로 소개했습니다.

**값은 그대로이고 성능은 올랐다고 발표됐습니다.** API 가격은 GPT-6 Sol과 같은 입력 $2 / 출력 $10(100만 토큰당)이고, 캐시 입력만 $0.20에서 $0.10으로 내려갔습니다. OpenAI는 상위 모델 GPT-6 Astra에 가까운 성능을 Astra 가격의 1/5로 낸다고 발표했습니다. 이 성능 수치는 OpenAI 발표이고 독립 비교는 아직 적습니다.

**Codex에서 두 가지를 주의합니다.** Codex에서 GPT-6.1 Sol의 기본 effort는 low라서(GPT-6 Sol은 medium), effort를 빠뜨리면 낮은 수준으로 돕니다. 하네스는 원래 effort를 항상 명시하므로 이 규칙을 문서에 분명히 적었습니다. 또 Codex의 ultra는 작업을 하위 에이전트에 자동으로 나눠 맡기는 수준이라 Orca 워커에 쓰지 않도록 했습니다.

## 확인한 사실

| 항목 | GPT-6 Sol | GPT-6.1 Sol | 출처 |
|---|---|---|---|
| 발표 | 2026-09-22 | 2026-09-29 | 보도 |
| 등록 ID | `gpt-6-sol` | `gpt-6.1-sol` | Codex 모델 목록, 보도 |
| API 가격 (입력 / 캐시 입력 / 출력, 100만 토큰당) | $2 / $0.20 / $10 | $2 / $0.10 / $10 | 보도 |
| 컨텍스트 / 최대 출력 | — | 1,050,000 / 128,000 토큰 (Codex 기본 272,000) | 보도, Codex 모델 목록 |
| 지원 effort | Codex: low, medium, high, xhigh, max, ultra | API: low, medium, high, xhigh, max. Codex는 ultra 추가 | 보도, Codex 모델 목록 |
| 기본 effort | Codex medium | API medium, Codex low | 보도, Codex 모델 목록 |
| Codex 목록 설명 | "Previous generation workhorse model." (목록에 남아 있음) | "Latest workhorse model for coding and everyday work." (목록 1순위) | Codex 모델 목록 |
| 지식 기준일 | — | 2026-04-30 | 보도 |

- Codex 모델 목록은 `openai/codex` 저장소의 `codex-rs/models-manager/models.json`(2026-09-30 커밋 `67727e7`)을 직접 읽어 확인했다. ultra의 정의는 "Maximum reasoning with automatic task delegation"이고, GPT-6.1 Sol에서는 하위 에이전트 작업을 xhigh로 돌린다.
- Codex CLI는 0.159.1(2026-09-29)과 0.159.2(2026-09-30, 현재 latest)가 npm에 올라와 있다. 목록상 최소 클라이언트 버전은 0.153.0이다.
- OpenAI 발표 수치(모두 OpenAI 측 측정): DeepSWE v1.1에서 GPT-6 Sol 최고 점수보다 6.4%p 높고 더 낮은 effort·비용으로 달성, OSWorld 2.0 7%p 향상, AutomationBench 4.8%p 향상, low effort의 사실 오류 응답 비율 11.4% → 7.7%, 명시적 제약을 지키는 평가에서 실패 감소.

## 판단

| 항목 | 결정 | 이유 |
|---|---|---|
| 모델 이름·ID | GPT-6.1 Sol / `gpt-6.1-sol`로 교체 | 사용자 요청. ID는 Codex 모델 목록에서 확인 |
| 선택 표·리뷰 표·대체 모델 표 | 유지 | 가격이 같고, 공식 소개가 연계 역할과 맞는다. 성능 향상은 제조사 발표뿐이라 표를 바꿀 근거로 쓰지 않고 `orca-runs.md` 기록으로 판단한다 |
| effort | 위험도 기준 유지 (medium, high, xhigh 모두 지원) | 지원 수준 확인 |
| Codex 기본 effort | 규칙에 명시 (Claude Code xhigh, Codex의 GPT-6.1 Sol low) | 지정을 빠뜨리면 low로 실행됨 |
| ultra | Orca 워커에 쓰지 않음 | 하위 에이전트 자동 위임이 "워커는 다른 에이전트를 띄우지 않는다" 규칙과 세션 예산에 어긋남 |
| GPT-6 Sol | 배정하지 않음 | Codex 목록에 남아 있어 헷갈리지 않도록 명시 |
| 코디네이터 | 유지 (Sonnet 5.5, 필요 시 Opus 5.5) | Sol은 구현·리뷰 부담이 커 코디네이터를 겸하지 않음 |

## 실행한 검증

- template mode `validate.sh`·`validate-quick.sh` 통과, 두 스킬 트리 동기화 통과, `git diff --check` 통과
- 바뀐 문서의 상대 링크 존재 확인
- 변경 기록과 ADR-002 배경(원래 프롬프트 인용) 밖에 `GPT-6 Sol`·`gpt-6-sol` 표기가 남지 않았는지 확인
- 선택 표 교차 확인: 모든 칸에 다른 회사 리뷰 모델과 대체 모델이 있고, 위험 높음의 대체 모델은 GPT-6.1 Sol·Opus 5.5뿐

## 남은 확인 항목

- 사용자의 Codex CLI 모델 목록에 `gpt-6.1-sol`이 보이는지는 코디네이터가 시작 확인에서 본다. 이 확인은 공개 저장소의 모델 목록 기준이다.
- OpenAI 발표 페이지와 API 문서는 이 환경의 네트워크 정책으로 직접 열지 못했다. 가격·컨텍스트·effort는 여러 보도와 Codex 모델 목록이 일치하는 값만 적었다.
- 곧 나온다고 발표된 GPT-6.1 Sol Ultrafast(Codex에서 최대 8배 빠른 생성)는 아직 목록에 없어 배정하지 않는다.
- 성능 향상 발표가 실제 Story에서 반려·재작업 감소로 이어지는지는 `orca-runs.md`의 Sol 칸 기록으로 확인한다.
