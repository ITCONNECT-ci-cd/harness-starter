# Astra / High 및 역할별 모델 배정 — 2026-09-10

일반 작업 기본값을 Astra / Extra High에서 Astra / High로 조정하고, 역할별 하위 에이전트 프로필과 [모델 배정 규칙](../agents/model-routing-rules.md)을 추가했습니다. 2026-09-09 기록은 당시 변경 이력으로 보존합니다.

| 역할 | 설정 | 적용 범위 |
|---|---|---|
| 주 에이전트 기본값 | Astra / High | 일반 Story·수정·최종 통합 |
| harness_planner | Astra / Extra High | 복잡한 Epic의 계획·의존성 검토, 읽기 전용 |
| harness_worker | Sol / High | 명확하고 독립적인 구현. 로컬에서 구현 위임을 허용할 때만 |
| harness_explorer | Sol / Medium | 조사·코드 탐색·로그 분석, 읽기 전용 |
| harness_reviewer | Astra / High | 일반 독립 리뷰, 읽기 전용 |
| harness_deep_reviewer | Astra / Extra High | 어려운 오류·동시성·권한/데이터 경계 분석, 읽기 전용 |

모델 값의 정본은 [프로젝트 설정](../../.codex/config.toml)과 `.codex/agents/harness-*.toml`입니다. 역할 파일에는 모델과 reasoning을 함께 지정했습니다. 기존 사용자 모델 선택·프로젝트별 위임·검증·독립 승인 정책은 유지합니다. 주 에이전트의 실행 중 모델을 자동 전환하는 기능은 추가하지 않았습니다.

## 배포와 보존

- 두 설치 스크립트에 역할 파일 5개를 개별 항목으로 추가했습니다. `.codex/agents` 전체를 교체하지 않으며 기본 설치는 같은 이름의 기존 파일도 보존합니다.
- 기존 프로젝트에는 새 규칙을 연결하고 허용된 역할만 배포합니다. 직접 구현 정책이 있는 프로젝트에는 worker를 배포하지 않습니다. 기존 BMAD 스킬과 다른 커스텀 역할은 수정하지 않습니다.
- 읽기 전용 역할은 지침과 프로필의 sandbox 설정을 갖지만 실행 환경의 상위 권한·런타임 설정이 우선할 수 있습니다. 생성 시 설정과 실제 실행 정보를 구분해 확인합니다.
- 역할별 파일은 Codex용이며 Claude Code 모델이나 BMADX 외부 실행 설정을 바꾸지 않습니다.

## 실행한 검증

- TOML 필수 필드·모델/추론 값, Bash 설치 스크립트 구문, PowerShell 설치 스크립트 AST, `git diff --check`를 확인했습니다.
- native `scripts/validate.ps1`: template 보안·성능·blocking 통과. 제품 설치/typecheck/lint/test/regression/build 6단계는 실행 대상이 없어 제외됐습니다.
- 격리된 설치 fixture에서 실제 native 복사 함수를 실행해 새 역할 파일 복사, 같은 이름의 기존 역할·다른 커스텀 역할·사용자 config 보존을 확인했습니다. 두 설치 매니페스트의 역할 경로도 대조했습니다. 실제 원격 다운로드나 전체 설치는 실행하지 않았습니다.
- 모델을 명시해 요청한 Astra / High 독립 소스 리뷰에서 중요한 확정 결함을 찾지 못했습니다. Sol / High 정책 감사로 각 대상의 기존 위임 제한과 역할 충돌을 확인했습니다.
- Sol / Medium 읽기 전용 배정 시험에서 작은 수정의 직접 처리, 명확한 구현의 worker 선택, UD 구현 위임 제한, 인증 오류의 모델 상향 금지, 단일 심층 리뷰어 선택을 확인했습니다. 실제 구현·에이전트 자동 생성 시험은 아닙니다. 호출 이름은 파일명 대신 TOML의 `name`을 사용하도록 명시했습니다.
