# 기존 프로젝트 하네스 적용

기존 프로젝트는 "안전한 통합"이 우선입니다. 새 파일을 무작정 덮어쓰지 말고,
기존 규칙과 충돌하는 부분만 백업 후 조정합니다.

더 긴 자동 통합 프롬프트가 필요하면 [../../README-brownfield.md](../../README-brownfield.md)를
참고하세요. 루트 README에는 비개발자가 바로 쓸 수 있는 짧은 프롬프트만 둡니다.

## 원칙

- 기존 사용자 변경과 harness 설치 산출물을 분리해서 봅니다.
- 기존 CI, Docker, DB, 배포 설정은 사용자 확인 없이 위험하게 바꾸지 않습니다.
- 기존 프로젝트가 이미 쓰는 테스트/빌드 명령을 우선합니다.
- `harness.validate.json`은 기존 명령 이름이 표준과 다를 때만 추가합니다.

## 적용 순서

1. 현재 git 상태를 확인합니다.
2. 기존 문서와 스크립트를 읽습니다.
3. 하네스와 충돌하는 규칙을 찾습니다.
4. 수정 계획을 먼저 보고합니다.
5. 승인된 범위만 수정합니다.
6. 현재 OS에 맞는 검증 진입점을 실행합니다.

## 충돌 예시

| 기존 내용 | 하네스 기준 |
|---|---|
| main에 직접 push | story/* -> develop -> main |
| DB migrate 직접 실행 | db-migrate 래퍼 사용 |
| docker compose down -v 허용 | 볼륨 삭제 금지 |
| 검증 실패 무시 | 로그 확인 후 수정 또는 명시적 예외 |
